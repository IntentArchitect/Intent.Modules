### Version 1.0.0

- New Feature: Guides AI agents through a four-phase module-building workflow with bundled skills, and an agent gate for Claude Code, Codex, GitHub Copilot CLI, Cursor, Kiro and OpenCode that blocks hand-edits to Intent Architect metadata and invalid version changes.
- Fixed: On Linux and macOS the agent gate misread an application's `location` written with Windows backslashes, so close-out attributed changes to the wrong module and the version guard silently allowed every version change; an application whose output folder holds other modules is also no longer mistaken for one of them.
- Fixed: The `.imodspec` guard denied a version edit that merely carried the unchanged `<summary>` line as context, and allowed an edit that deleted `<summary>` outright; it now compares the field before and after.
- Improvement: The agent gate now guards the Intent MCP server's `write_file`, `patch_file` and `delete_code_file` on every harness, and reads Cursor's MCP payloads, whose tool input arrives as a JSON string.
- Improvement: The workflow instructions tell the agent to fix a gate failure caused by its own working directory itself, and what to do when the changed module cannot be installed.
- Improvement: `module-dependency-audit` names where dependencies come from and the hard-coded `Intent.Common`/`Intent.Common.CSharp` floors, offers a metadata-only install or a hand-added `<dependency>` with their trade-offs, and covers an install that cannot be done; `module-docs-chore` and `module-version-increment` correct what the Software Factory writes, and `module-docs-chore` never labels anything beta or pre-release.
- Improvement: Depends on `Intent.Common` 3.11.8, whose Markdown parser no longer splits a bullet that wraps onto a second line.
- Fixed: After a `cd` into a module folder, Claude Code could no longer find the agent gate and every guarded edit was blocked; the merge into `.claude/settings.json` now sets `CLAUDE_BASH_MAINTAIN_PROJECT_WORKING_DIR` (only when you have not set it), so Claude Code's shell returns to the project directory after each command. The setting covers the main session only; a sub-agent's `cd` can still move the hooks, and the workflow instructions tell the agent how to recover.
- Fixed: When the gate's hook entry shared a matcher group with your own hooks in `.claude/settings.json` or Codex's `hooks.json`, updating the gate rewrote that shared group's matcher; the gate's entry now moves to a group of its own and your hooks keep their matcher.
- Improvement: The workflow instructions skip every phase for an edit that only changes comments or formatting in a module's own code. For large work, such as a specification or a new module, they say to template only code patterns proven in hand-written, tested reference code, to stop and ask the developer when a pattern has none, and to ask about review checkpoints when the developer gave no plan. The gate's close-out warning about an unmoved version now says it does not apply to such an edit.
