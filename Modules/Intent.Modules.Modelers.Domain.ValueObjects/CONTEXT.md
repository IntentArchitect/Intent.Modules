# Context: Intent.Modelers.Domain.ValueObjects

## Purpose
Adds the `Value Object` element to the Domain designer, and extends the Domain designer's own elements and `Association` type so Value Objects can be used as attribute, operation, parameter and association-end types. It is designer metadata only; code is generated by other modules (e.g. Intent.ValueObjects, persistence modules).

## Architectural Decisions
- **The Value Object `New Association` context menu offers composite relationships only**: `One to One`, `One to Zero-or-One` and `One to Many`, and clicking `New Association` itself defaults to `One to One`. The developer decided Value Objects must not have aggregate relationships; a Value Object is always owned by exactly one source. It started as a full copy of the Domain `Class` menu (nine options, defaulting to `Many to One`); the `Many to …` and `Zero-or-One to …` options were removed because they describe aggregates, and the macro below would have turned them into `One to …` anyway. The shortcut (`ctrl + shift + c`) matches the Class menu.
- **A Value Object → entity (`Class`) association is a designer validation error, not removed from the allowed types.** The `Value Object` element's `Validate Function` flags any `Association` where the Value Object is the source and the target is a `Class`. No downstream module supports that association: Intent.ValueObjects and CosmosDB ignore non-Value-Object targets (Intent.ValueObjects' README: Value Objects should not refer back to the entities that own them), and EF Core throws a NullReferenceException in the Software Factory. The Domain designer's key automation also adds a foreign-key attribute (e.g. `CountryId`) to the Value Object, which has no place on an immutable value. Validation was chosen over deleting the association in the `on-changed` macro (silent, and only acts on change), a separate Value-Object-only association type (persistence modules only read the Domain `Association`), and reverting the menu (loses Value Object → Value Object). Validation is the soft option: models that already contain such an association, possibly created by others, are flagged rather than altered.
  - Superseded the first 3.6.5 decision to keep `Class` targets for the new menu. That was the agent's inference, made before checking downstream modules.

## Invariants & Constraints
- **A Value Object at the target end is always owned by exactly one source.** The `Association Extension`'s `on-changed` macro sets the source end to non-collection and non-nullable whenever the target end's type is a `Value Object`. That holds whichever menu option created the association.
- **Module Builder cannot make allowed targets depend on the source (SDK limitation).** The source and target end extensions add `Value Object` to the Domain `Association`'s own allowed types, which already include `Class`, and the lists apply to every association. Allowing Value Object as a source (needed for Value Object → Value Object) therefore also allows Value Object → `Class`. Association end extensions have no validate hook either, so the rule lives on the `Value Object` element's `Validate Function`. Value Object → `Class` has been reachable this way since the module was created (`0f1ba98ac`, 2022), probably by accident; the 3.6.5 menu only made it reachable by right-click.
- **Not flagged: a Class → Value Object association that is navigable both ways.** It also gives the Value Object a reference to the entity, but it was left out to keep the validation narrow until there is evidence it causes problems.

## Module Interactions
- **Intent.Modelers.Domain**: owns the `Association` type (`Association Settings`) and its `Association Target End` specialization, which both the Association Extension and the Value Object `New Association` option point at.
  - Written against 3.9.0.
- **Intent.ValueObjects and the persistence modules** (EF Core, CosmosDB, MongoDb, DynamoDB, Redis OM, Table Storage, Dapper): consume Value Object associations; none supports a Value Object → entity association, which is why it is a validation error here.
