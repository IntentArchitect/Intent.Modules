### Version 1.3.0

- New: Added a `Classify Files` designer script, which Change Review runs to classify files without showing a form. It matches the classification by name (ignoring case), creating it in a `File Classifications` folder when unknown, and writes a `File Classification` entry for the file, or for its folder and extension (a file with no extension uses its exact path), on the element that governs it. It reports failures as errors, and needs a Change Review that calls it.

### Version 1.2.0

- Improvement: `Custom File Classification` is renamed to `File Classification`, its entry stereotype to `File Classification Entry`, and its `Severity` property to `Review Importance`, which better describes how important it is to review changes to a file. Existing data keeps working.
- Improvement: `File Classification` can now be applied to `Template Output`s, so different files generated by the same template can carry different classifications. Globs are evaluated relative to the folder containing the `Template Output`.
- Fixed: `File Classification` could not be applied to the Root Folder, so files at the application's output root (e.g. `NuGet.Config`, `.editorconfig`) could not be classified. Its globs there are relative to the application's output location, and deeper folders and projects still take precedence.
- Improvement: A `File Classification` element's icon is now tinted with its `Color`, and with `Color (Dark Mode)` in the dark theme (each falling back to the other, then to the colour derived from its name), matching its pill in Change Review, instead of always being blue.
- Improvement: Module install now stamps a single `**/*` entry of `File Classification` on `Template Output`s instead of `Output Classification`.
- Improvement: A migration converts existing `Output Classification`s into an equivalent `File Classification` with a single `**/*` entry, and the `Output Classification` stereotype has been removed.
- Improvement: Rewrote the descriptions of the `File Classification` stereotypes, their properties and the `File Classification` element so that both people and AI agents can tell how to apply them, how rows combine, and what each field means.
- Improvement: Now requires Intent Architect 5.4.0-beta.6 or later, so that module install stamps the new shape.

### Version 1.1.2

- Improvement: `Custom File Classification` entries now display as `[Severity - Classification] glob, glob` making them easier to scan when several are applied.
- Improvement: Clarified that where multiple `Custom File Classification` entries match the same file, the last matching entry wins, so broad catch-all entries should be placed first with exceptions below them.
- Improvement: If `Intent.VisualStudio.Projects` is already installed, it will be updated `4.1.10` so that Solution Folders and .NET projects also allow adding of the `Custom File Classification` stereotype them.

### Version 1.1.1

- Improvement: `Custom File Classification` stereotype now has an "Entries" property which allows multiple values instead of the stereotype needing to be applied multiple times.
- Improvement: The `Allows Custom File Classification` is now stored packages to reduce git commit noise.

### Version 1.1.0
